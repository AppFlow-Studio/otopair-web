## Phase 1 — Enrichment foundation: parts pricing + per-role resolution

### `14b7e63` — feat(enrichment): deterministic parts pricing + robust-median labor times

**What changed.** The foundational rewrite of how the enrichment pipeline derives the two numbers that feed every quote: per-part prices and per-service labor times. Five mechanisms land together (32 files, +2678/−653):

1. **`convex/vehicleEnrichment/priceParser.ts` (new)** — a pure, ctx-free OEM price extractor. `parsePartPrices(html, sourceUrl): ParsedPartPrice[]` + `normalizeOemNumber(raw)`. A three-layer cascade over **raw HTML** (not flattened markdown): (a) **JSON-LD** — scans `<script type="application/ld+json">`, `JSON.parse`s (malformed → skip, never crash), recursively walks `@graph`/`itemListElement`/`item` to gather every `schema.org/Product`; price from `priceFromOffers` (handles a single Offer, an **array of Offers** → `Math.min` of positives = "what a buyer actually pays," and `AggregateOffer.lowPrice`/`priceSpecification.price`); OEM from `mpn ?? sku ?? productID ?? gtin13`. (b) **microdata/OpenGraph** meta tags. (c) **per-domain DOM fallback** — a `DOMAIN_SELECTORS` registry (RevolutionParts storefront family) targeting `.price-section-price` and **deliberately never** `.price-section-retail` (MSRP) / `.price-section-save` (You Save); fires **only on registered domains**. Results dedupe by normalized OEM (first wins); sub-4-char numbers rejected.
2. **`convex/lib/robustStats.ts` (new)** — `median`/`nonOutlierIndices` extracted verbatim from `part_prices.ts` (behavior-preserving) plus `percentile` and `summarizeObservations(values, weights?)`: drops non-finite/≤0, MAD outlier rejection (modified z-score, threshold 3.5, keeps all when <4 samples or MAD 0), **median over all valid values unweighted** (the robust headline must not be weight-skewed) + **average over the non-outlier subset, optionally weighted**. No weights → reproduces the original mean exactly.
3. **`convex/lib/labor_aggregation.ts` (new)** — `recomputeLaborForConfigService`. Replaces "highest-confidence source wins" (which made Vehicle Databases the de-facto truth) with the parts-pricing shape. Catalog tier: robust median over append-only `labor_observations` → `book_hours`, clamped `[0.1, 8.0]h`, rounded 0.1h. Empirical tier: `collectEmpiricalHours` over finalized `job_actuals` but **only single-service bookings** (multi-service has one un-splittable `actual_labor_minutes`) whose vehicle config matches; overrides book time only at `LABOR_EMPIRICAL_MIN_SAMPLES = 3` (else cleared to 0 → falls back to book). `bookOnly` (the scrape path) skips the `job_actuals` scan.
4. **`convex/part_prices.ts`** — `quoteUnitPrice({average, median, sample_size})`, gated behind `process.env.PARTS_PRICE_SOURCE`: `"median"` returns the median only at ≥3 sources (else outlier-rejected mean); default `"average"` = legacy. `booking_quotes.ts` and `job_actuals.ts` switch from raw `summary.average` to `quoteUnitPrice(...)` (reversible because median isn't outlier-protected at small n).
5. **Schema** — `firecrawl_cache` gains `part_prices_json` (carries `ParsedPartPrice[]` from scrape to price-write) + `format_version` (old markdown-only rows count as a miss); new `price_backfill_log` (snapshots every deleted legacy row, for reversibility); new append-only `labor_observations` (`{vehicle_config_id, service_id, engine_family?, hours, source, tier, weight, observed_at}`, three indexes). `convex/vehicleEnrichment/backfills.ts (new)` — `backfillPartPrices`, flag-gated (`BACKFILL_PARTS_PRICES=on`, default dryRun), keyed off each row's `source_url`: re-fetch → re-parse → write correct `"sale"` for any URL whose JSON-LD has this part's exact OEM, **then** prune that part's poison rows (snapshotting first); a part whose price can't be re-derived keeps its old row. `convex/crons.ts` — `recompute-recent-labor` every 6h.

**Why.** Two live pricing bugs. Price: the pipeline read *flattened markdown* where the real price, struck MSRP, and "You Save $X" collapse into ambiguous text — quoting `$11` instead of `$104`. Labor: a single high-confidence source (VDB) dictated every labor time with no way for real shop data to correct it. The redesign makes both a robust median over independent observations so no single bad value dominates.

**How it works.** Scrape → `parsePartPrices` over raw HTML → deterministic `"sale"` prices on `firecrawl_cache.part_prices_json` and per part. At quote time `summarizePartPrices` (now backed by `robustStats`) → `quoteUnitPrice` selects median-or-mean. Labor: `labor_observations` → robust median `book_hours`, with empirical post-job medians taking over per `(config, service)` once ≥3 real single-service jobs complete.

**Tests.** `tests/priceParser.test.ts` (proves JSON-LD returns the real sale price and **never** MSRP 139.33 / You-Save 34.83; numeric coercion; `@graph` multi-product; skips cross-sell tiles without an OEM; `AggregateOffer.lowPrice`; offers-array lowest not first; malformed JSON-LD safe; DOM fallback ignores `-save`/`-retail`; **registry selectors do NOT fire on unregistered domains**). `tests/robustStats.test.ts` (median odd/even/empty, percentile interpolation, MAD rejection at ≥4 samples, `summarizeObservations` zero-handling + median-all/avg-non-outliers). 22 green unit tests.

## Phase 3 — Labor-time RepairPal source + sibling resolution

This sprint replaces the unreliable per-vehicle labor catalog (bad VDB repair-estimates + unvalidated LLM book times) with MOTOR-grade labor recovered from RepairPal's public estimator, weighted-aggregated, and surfaced with a tiered "data-good" confidence signal. The core insight: RepairPal exposes labor **dollars** at a fixed national rate range, so hours are recoverable arithmetically; and labor is a function of **chassis_code + engine_family**, not the nameplate, so niche cars with empty RepairPal pages can source labor from a *validated platform-equivalent sibling*. Ships dark behind `LABOR_SOURCE_REPAIRPAL`.

### Design & plan
- **`2d828d2`** docs(spec): RepairPal/MOTOR source design. Establishes the probe evidence — the labor-$ `high/low` ratio is a constant ~1.47 across every probed service/vehicle, proving `labor$ = MOTOR_hours × rate`, so `hours = midpoint ÷ RATE_MID (≈$130/hr)`. Source weights (repairpal 0.8, llm_web 0.5, llm_training 0.3, vdb 0.05).
- **`e009ac8`** docs(spec): v2 — sibling resolution. Central idea: coverage is nameplate-gated; the niche M550i has a directory page but **empty** estimates, while the M550i and 550i xDrive bill identical labor (both G30 + N63). Introduces service-determinant routing (engine jobs match by `engine_family`, chassis by `chassis_code`, some `both`), the resolution ladder (exact → both-match twin → single-key sibling → LLM/VDB/default), **LLM-as-router-not-source**, and three validation gates (populated-page, platform-confirmation, agreement).
- **`91d8dff`** docs(plan): 924-line TDD task-by-task plan with file table + two milestones, followed verbatim by the commits below.

### `d5cab59` — security(oto): internalize unauthenticated memory/fact/KB/telemetry writers (P1)

### `39828c7` — perf(oto): 1h prompt-cache TTL + gate the per-turn envelope log (B-P4)
**What changed.** The system+tools cache breakpoint switches from the default 5-minute ephemeral TTL to `ttl:"1h"` (GA — no beta header).
