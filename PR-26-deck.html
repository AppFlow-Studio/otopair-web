P1
Enrichment · Parts pricing // 14b7e63 · 9025ad0

Quotes that match the real invoice.

Before

The parser read flattened markdown, where the sale price, the struck MSRP and "You Save $X" collapse into one blob — so it quoted $11 instead of $104. And one "winner" was chosen across all of a service's parts, so an oil change billed a single bottle, no filter, no washer.

→
After

A pure extractor reads raw HTML / JSON-LD and deliberately never touches MSRP or "You Save." Parts resolve per role from a canonical 23-service reference, and fluids price by capacity (4.8 qt → 5 bottles). Every line on the quote is auditable.

Why it mattered

Customers were shown prices that were simply wrong — sometimes off by 10× — and multi-part jobs were structurally under-quoted.

Benefit

The quote now reflects every part at the right quantity at the price a buyer actually pays. Backed by a 22-test parser suite + a reference-contract suite.

P2
Enrichment · Price re-extraction // b597c4b · 3427406 · 0cd043d

One contract for every price writer.

  • Two-tier extraction — structured JSON-LD first (free, exact), then an LLM fallback whose prompt explicitly forbids MSRP / "was" / struck-through figures and echoes back what it saw so guardrails can reject a wrong grab.
  • Poison-exclusion median — bad price types are filtered before the math, so a figure only 20–40% off (which survives outlier rejection) can never drive the customer price.
  • A strict outcome contract — sale / unverified / fetch_failed. A transient scrape failure no longer deletes a good price; a page that contradicts its own number is marked, not trusted.
  • No silent $0 — an unpriceable part is flagged price_unknown ("confirmed post-job") instead of billing $0 as if it were real.
Why it mattered

Four separate paths wrote prices and could drift; transient failures were quietly erasing verified prices.

Benefit

Director reprice, enrichment, admin backfills and the aggregator now share one verified contract. Live: a Jetta's poison rows went 16 → 0.

P3
Enrichment · Labor times // RepairPal source

MOTOR-grade labor, even for niche cars.

  • RepairPal exposes labor dollars at a fixed national rate — the high/low ratio is a constant ~1.47, so hours are recoverable arithmetically (hours = midpoint ÷ rate).
  • A source-weighted median means no single bad reading dominates; the old VDB "winner" is demoted to a tiebreaker.
  • Sibling resolution — labor is a function of chassis + engine, not the nameplate. A niche M550i inherits from a validated twin: 750i (same N63) or 530i (same G30).
  • The LLM is a router, not a source — it only picks which page to read; three validation gates mean a wrong sibling can never supply a number.
Why it mattered

Labor times were dictated by a single unvalidated source, with no way for real shop data to correct them — and the lowest-volume cars had no coverage at all.

Benefit

A tiered "data-good" confidence signal the quote engine can gate on. Real shop jobs silently take over once 3+ complete.

P4
Enrichment · Robustness // 41c07de · 56e1d51 · 3e6f1b5

Runs that finish. Cars that come out priced.

The failure modes

A TLS-dead supplier made the scraper burn the full 600s action cap before any work landed — leaving the car stuck "enriching" forever, blocking bookings. Fresh cars came out fully discovered yet fully unpriced. An M340i and a 330i shared one cache for 30 days.

→
The fixes

A scrape time-budget caps each page and the loop. A failure handler + force-unstick always restores the car to a terminal state and lets a director take over a dead run. Batch-2 now prices the parts it discovers itself. Trim is in the cache key.

Why it mattered

A stuck config breaks the booking soft-lock, and an unpriced car can't be quoted at all.

Benefit

First convex-test coverage of the enrichment action layer (7 tests). Live: a Civic that failed twice now completes and prices 8 → 23 parts.

P4
Enrichment · Data correctness // ca40fae · ce6b386

Human fixes that stick.

  • An engine field a human corrected (the EA211 is belt, not chain) was silently overwritten on the next re-enrich — and because applicability nulls are final, a misclassified car could never get its belt parts.
  • Now every human-changed field is stamped verified_fields; the pipeline skips verified keys and applies them before the applicability rules run.
  • A small curated engine-facts table protects future cars of the same family — physical facts about an engine don't need an LLM vote.
Why it mattered

Correct data was being clobbered by the very process meant to refresh it — and the dependent parts (belt + kit + water pump) could never populate.

Benefit

Verified data now steers re-enrichment instead of being overwritten by it. Every fix is audit-logged with a before→after diff.

SEC
Security // aff697e · f13dea5 · d5cab59 · 845edbb · aa0d79c · 0a5c891

Closing an IDOR class.

The exposure

~13 public, unauthenticated mutations let anyone with the URL write any user's persistent memory (durable stored prompt injection at confidence 1.0), the shared knowledge base, and the forensic audit log. Director panels leaked email + phone + full transcripts. The audit log leaked director emails. The MCP DB route failed open.

→
The lockdown

Server-side writers → internalMutation (every caller is server-side). User tables → owner-gated on ctx.auth. Director surfaces → session-token gated, audit actor derived from the session (no forgery). The MCP route now fails closed.

Why it mattered

Same bug class we'd closed on enrichment, swept across Oto + the admin surface. Verified by a 6-agent caller audit — zero client callers, so nothing breaks.

Benefit

A whole exploit class — memory poisoning, PII leaks, forged audit trails — is closed, each with a dedicated auth-gate test suite.

B1
Oto · Telemetry // c46b1c7

Making "is Oto good?" measurable.

Before

Every production telemetry row recorded 0 tokens, an empty tool list, and model = "haiku" regardless of what actually ran — because the aggregation only worked on debug runs, and the insert stamped a constant. Cost-per-booking was literally unmeasurable.

→
After

A pure assembler sums real per-turn samples collected unconditionally inside the tool loop, and stamps the routed model. Tokens, latency, tools, branch — all real, all per turn.

Benefit

The whole question the review was built to answer — quality and cost — is now backed by real numbers, surfaced in the new viewer's debug pane.

B2
Oto · Routing & memory // 7c0d078 · 8b390fe · 307f159

The smart model answers the hard turn.

  • Same-turn Sonnet escalation — the turn that asked for Sonnet was still answered by Haiku; Sonnet only engaged the next turn. Now it answers the hard diagnostic turn it was escalated for.
  • The vehicle anchor finally fires — "one chat, one car" had zero production call sites, so every conversation's car was blank. Now locked on first send.
  • No cross-car fact bleed — the knowledge-base cache keyed only on the question, so one car's fact was served to another car's owner. Now scoped by chassis / engine / config.
  • The state contract is now measured — a reliability event fires when a substantive turn skips writing its memory, so under-calling is visible and tunable.
B3
Oto · Tool-schema truth // 593b155 · 9236179 · e2a07a2

Tools that tell the truth.

Before

Tool descriptions disagreed — some said "VIN", the code expected an id — so a VIN threw and list_services_for_vehicle silently fell open to the unfiltered catalog (offering an oil change on an EV). Live descriptions pointed at dead tools, so Oto fabricated mechanic ids. Web-search pauses dead-ended into a generic apology.

→
After

One resolver accepts VIN-or-id everywhere. The 9 dead tools are stripped and the fabricated-id descriptions rewritten. pause_turn now continues the search instead of giving up.

Benefit

The last real correctness bug — applicability silently failing open — is closed, plus the "ask Oto to look something up" path no longer dead-ends. Guarded by a regression test that fails if any description references a removed tool.
